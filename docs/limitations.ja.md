# 限界

English: [limitations.md](limitations.md)

このツールが見落としうるもの、判定できないもの、その理由。「何も見つからない」は「安全」ではありません。

## 見落としうるコピー

- **探索する場所の外。** 既定は `/opt, /usr/local, /srv, /var/www, /home, /root` と、システムの Python・
  ライブラリのディレクトリ。それ以外は `--roots` で指定してください。
- **アーカイブや、動いていないイメージの中**: `.asar`・`.jar`・`.zip`、AppImage・squashfs のファイル、
  実行中のコンテナが無いコンテナイメージ、仮想マシンのディスク、バックアップ。
- **印の無い静的なコピー。** `--deep` は、同梱のデコーダーを公開シンボル名（`BrotliDecoderDecompressStream`
  など）かエラー名の文字列で見分けます。完全に strip され、リンク時最適化され、`BrotliDecoderErrorString`
  を使わないバイナリはどちらも持たないことがあり、その場合は見えません。
- **ネットワークファイルシステム**（NFS・CIFS・sshfs など）。`--include-remote` を付けない限り探しません。
- **ほかの実装。** Go（`andybalholm/brotli`）、Rust（`brotli-decompressor`）、Java・.NET のデコーダーは別の
  コードで、調べません。それらがこの CVE の影響を受けるかは、ここでは扱いません。
- **snap／flatpak 以外で入れた Electron アプリ**は `--deep` のときだけ見つかります。
- **Alpine ベースのコンテナ**（apk）は、中のパッケージを判定しません（`--inspect-containers` が扱うのは
  Debian/Ubuntu ベースのイメージと、Node.js・PyPI のコピー）。
- Linux のみ。パッケージの判定は Debian・Ubuntu とその派生のみ。

## root でないとき

他ユーザーのプロセス（C03、C04 の再起動の確認、C15 のソケットの持ち主）、`/root`、読めないホーム
ディレクトリは見えません。結果の「走査しなかった範囲」に並びます。

## 文字列による推定（LIKELY_FIXED／LIKELY_VULNERABLE）

修正でデコーダーのエラー `_ERROR_FORMAT_BLOCK_SWITCH`（-17）が追加され、`BrotliDecoderErrorString` は
エラー一覧から名前を作ります。検証結果（[tests/fixtures/c09/README.md](../tests/fixtures/c09/README.md)）:

| ビルド | 未修正（1.2.0） | 修正済み（1.2.1） |
|---|---|---|
| 共有ライブラリ（strip の有無とも） | 名前 16 個、BLOCK_SWITCH なし | 17 個、BLOCK_SWITCH あり |
| 静的、-O2（strip の有無とも） | 同上 | 同上 |
| 静的、LTO＋gc-sections、`BrotliDecoderErrorString` を使うプログラム | 同上 | 同上 |
| 同上、使わないプログラム | **0 個** | **0 個** |
| Node.js 公式 22.23.3／22.23.4、24.22.0／24.22.1 | 16 | 17 |
| PyPI Brotli 1.2.0／1.2.1、brotlicffi 1.2.0.x／1.2.1.0 の wheel | 16 | 17 |

このため、推定はエラー名があるとき（8 個以上）だけ行い、無ければ `VENDORED_COPY` とします。1.0.10 と 1.1.1
の修正も同じエラーコードを追加しています（ソースで確認）。ただし検証のためのビルドはしていません。提供元が
別のやり方で直した独自の修正は印を持たず、`LIKELY_VULNERABLE` と出ます。ファイル名の版と文字列が食い違う
ときは `UNKNOWN` とします。

## 版番号

- 配布元のパッケージは配布元の修正版と比べます。既知データの日付より後に出た修正は分かりません
  （`NO_FIX_AVAILABLE` が古くなっていることがある）。データの日付を見てください。
- Debian の `nodejs` はシステムの libbrotli を使います（`libbrotli1` で判定）。静的にリンクした配布元の
  ビルドは、版に修正の取り込みが表れないことがあるため、文字列で判定します。
- Chromium と Firefox の基準はソースツリー（third_party/brotli、modules/brotli）からのもので、ベンダーの
  告知ではありません。Chrome と Chromium 以外の Chromium 系ブラウザ（Edge・Brave など）は版で判定しません。
- サポートが終わった Node.js の系列（20 以前・21・23・25）は導出で脆弱と報告します。Node.js の勧告が
  「サポートが終わった版は常に影響を受ける」としており、修正版が出ていないためです。10 以前は `UNKNOWN`
  （Brotli を同梱する前の可能性がある）。

## プログラムの実行

見つけたプログラムを実行するのは `--version`（または `-V`）のときだけで、環境変数を空にし、制限時間を付けます。
さらに、ファイルとその上のディレクトリがすべて root（root 以外で動くときは本人）のもので、他者が書き込めない
場合に限ります。root で動くときは、グループが書き込めるパスは実行しません。一般ユーザーで動くときは、
グループが書き込めるディレクトリは本人専用のグループ（名前が本人と同じ・本人の主グループ・その GID の項目が
1 つ・他のメンバーなし・他人の主グループでない）の場合だけ認めます。グループパスワード（`gshadow`）や、
ディレクトリサービスが列挙しないユーザーは確認できません。それが問題になる環境では `--no-exec` を使って
ください。それ以外はファイルから判定します。`ldd` にも同じ条件をかけ、満たさないときは `readelf` と
`ldconfig -p` でリンクを辿ります（変わった `RUNPATH` の設定は見落としうる）。`--inspect-containers` は、
実行中のコンテナの中で決まった読み取り専用のスクリプトを実行します。

## レポートの保存（`--output`）

`--output` は新しいファイルを作るだけで、既存のものを上書きも、開きもしません。保存先から `/` までのすべての
ディレクトリが root（root 以外で動くときは本人）の所有で、他のユーザーが書き込めないこと（`/tmp` のように
root 所有で sticky bit 付きなら可）が条件です。そのため root で動かすときは、一般ユーザーのホームには書けません。
そのディレクトリの持ち主が、root の書くファイルを別の場所へ向けられるためです。root で点検した結果を自分の
ホームに残すときは、標準出力をリダイレクトしてください: `sudo bash brotli-cve-check > report.txt`。

## 結果が意味しないこと

- 侵入の有無の確認ではありません。修正版に更新しても、更新前の侵入の痕跡は消えません。
- 他のホストや、動いていなかったコンテナについては何も言いません。
