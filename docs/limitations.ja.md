# 限界

English: [limitations.md](limitations.md)

このツールが見落としうるもの、判定できないもの、その理由。「何も見つからない」は「安全」ではありません。

## 見落としうるコピー

- **探索する場所の外。** 既定は `/opt, /usr/local, /srv, /var/www, /home, /root` と、システムの Python・
  ライブラリのディレクトリ。それ以外は `--roots` で指定してください。
- **アーカイブや、動いていないイメージの中**: `.asar`・`.jar`・`.zip`、AppImage・squashfs のファイル、
  実行中のコンテナが無いコンテナイメージ、仮想マシンのディスク、バックアップ。
- **印の無い静的なコピー。** `--deep` は、同梱のデコーダーを公開シンボル名（`BrotliDecoderDecompressStream`
  など）かエラー名の文字列で見分けます。完全に strip され、リンク時最適化され、`BrotliDecoderErrorString`
  を使わないバイナリはどちらも持たないことがあり、その場合は見えません。C11 の Web サーバーで「印が無い」を
  `NOT_APPLICABLE` とするのが、ソースを確かめた配布元のパッケージ（nginx・Apache・HAProxy）と cgo の Brotli を使わない
  Go のプログラムだけなのはこのためで、ほかのパッケージ、インストール後に変わったファイル、自分でビルドしたサーバーは
  `UNKNOWN` になります。残る穴は 2 つです。配布元のパッケージは名前・Maintainer・版の形で見分けるので、3 つとも保ったまま
  作り直したものは同じに見えます（dpkg の記録は、書いた人が正直である範囲でしか当てになりません）。cgo のバインディングで
  見ているのは `cbrotli` だけなので、ほかのバインディングで C の Brotli を組み込み strip した Go のプログラムは見えません。
  実行していない静的な curl も同じ理由で `UNKNOWN` です。
- **ネットワークファイルシステム**（NFS・CIFS・sshfs など）。`--include-remote` を付けない限り探しません。
- **シンボリックリンクの探索場所**はリンク先を探します（結果に書きます）。それ以外のシンボリックリンクは辿りません。
- **探す場所の下の、ほかのファイルシステム。** 探す場所の下にマウントされたローカルディスクは探します。tmpfs・
  overlay・squashfs・fuse などは探さず、「走査しなかった範囲」に並べます（`--roots` で指定すると対象になる）。
  マウントポイントではない btrfs のサブボリュームは探さず、並べもしません（`find -xdev` がそこで止まり、
  マウントの一覧にも出ないため）。
- **ほかの実装。** Go（`andybalholm/brotli`）、Rust（`brotli-decompressor`）、Java のデコーダーは別の
  コードで、調べません。それらがこの CVE の影響を受けるかは、ここでは扱いません。
- **.NET。** .NET のランタイムは別のコードではなく、Google の C のデコーダーを `libSystem.IO.Compression.Native.so` に
  組み込んでいて、Ubuntu はこの CVE の対象に挙げています（[USN-8958-1](https://ubuntu.com/security/notices/USN-8958-1)）。
  このツールは名前で探さず、`/usr/lib/dotnet` は既定の範囲に無いので、既定の実行では何も出ません。
  一覧に出すには `--deep --roots /usr/lib/dotnet` です（Ubuntu 24.04 で確かめた。`VENDORED_COPY` になります）。
  ランタイムの版を、Microsoft か配布元の告知と照らしてください（[#17](https://github.com/sakai-sktech/brotli-check/issues/17)）。
- **`libbrotlidec*` という名前のライブラリを複数読み込むプログラム。** 判定するのは最初の 1 つだけです。ほかのものは、
  探索の範囲の中にあるときだけ見つかります（[#18](https://github.com/sakai-sktech/brotli-check/issues/18)）。
- **別の名前のプログラムへのリンクである `node`・`bun` など**（`node -> runtime`）。バージョン管理ツールのシムをランタイムとして
  判定しないよう取らず、一覧にも出ません（[#19](https://github.com/sakai-sktech/brotli-check/issues/19)）。
- **RUNPATH・RPATH の中の `glibc-hwcaps` ディレクトリ。** 名前の順に試します。glibc は CPU が対応するいちばん高いレベルを優先します。
  複数のレベルにコピーがあると、判定して説明したものと読み込まれるものが違うことがあります（[#18](https://github.com/sakai-sktech/brotli-check/issues/18)）。
- **snap／flatpak 以外で入れた Electron アプリ**は `--deep` のときだけ見つかります。
- **Alpine ベースのコンテナ**（apk）は、中のパッケージを判定しません（`--inspect-containers` が扱うのは
  Debian/Ubuntu ベースのイメージと、Node.js・PyPI のコピー）。
- **このホストの unix ソケット以外でつないだコンテナ**（`DOCKER_HOST`、別の先を指す docker の context や podman、
  `tcp://localhost`、サービスにつないでいる podman）は、接続先と一緒に一覧と数を出しますが、中では何も実行しません。
  別のホストのソケットを ssh などでこのホストの unix ソケットに引いてきた場合は、このホストのものと見分けられません。
  podman の互換の `docker`（podman-docker）は接続先を答えないので、そのコンテナの中も見ません。
- Linux のみ。パッケージの判定は Debian・Ubuntu とその派生のみ。

## root でないとき

他ユーザーのプロセス（C03、C04 の再起動の確認、C15 のソケットの持ち主）、`/root`、読めないホーム
ディレクトリは見えません。結果の「走査しなかった範囲」に並びます。

## 文字列による推定（LIKELY_FIXED／LIKELY_VULNERABLE）

修正でデコーダーのエラー `_ERROR_FORMAT_BLOCK_SWITCH`（-17）が追加され、`BrotliDecoderErrorString` は
エラー一覧から名前を作ります。検証結果（[tests/fixtures/c09/README.md](../tests/fixtures/c09/README.md)）:

| ビルド | 未修正（1.2.0） | 修正済み（1.2.1） |
|---|---|---|
| 共有ライブラリ（strip の有無とも） | 名前 16 個、BLOCK_SWITCH なし | 17 個、BLOCK_SWITCH あり |
| 静的、-O2（strip の有無とも） | 同上 | 同上 |
| 静的、LTO＋gc-sections、`BrotliDecoderErrorString` を使うプログラム | 同上 | 同上 |
| 同上、使わないプログラム | **0 個** | **0 個** |
| Node.js 公式 22.23.3／22.23.4、24.22.0／24.22.1 | 16 | 17 |
| PyPI Brotli 1.2.0／1.2.1、brotlicffi 1.2.0.x／1.2.1.0 の wheel | 16 | 17 |

このため、推定はエラー名があるとき（8 個以上）だけ行い、無ければ `VENDORED_COPY` とします。1.0.10 と 1.1.1
の修正も同じエラーコードを追加しています（ソースで確認）。ただし検証のためのビルドはしていません。提供元が
別のやり方で直した独自の修正は印を持たず、`LIKELY_VULNERABLE` と出ます。ファイル名の版と文字列が食い違う
ときは `UNKNOWN` とします。

リンカーは同じ文字列を 1 つにまとめるため、デコーダーのコピーを 2 つ持つファイルでも名前は 1 組しか見えず、
修正済みのコピーが未修正のコピーを隠します。そこで Brotli に組み込まれた辞書のコピー（コピー 1 つに 1 個）を
数え、2 個以上なら `LIKELY_FIXED` ではなく `UNKNOWN` とします。辞書を 1 つ共有する 2 つのデコーダーや、
外部の辞書を使うビルドは見分けられません。そのため `LIKELY_FIXED` の行には、分かったこと（修正のエラー名がある、
辞書の数）と分からないこと（ファイルの中のデコーダーがすべて修正済みかどうか）を書きます。ファイルはサイズの
上限（512 MiB）まで読み、最後まで読めなかったファイルは `UNKNOWN` とし、「走査しなかった範囲」にも並べます。

プログラムからではなくファイルから読んだ版（ディレクトリ名・`node_version.h`・パッケージのメタデータ・
ライブラリのファイル名）で `FIXED` とするのは、ファイルの文字列が 1 つのコピーで修正を確かめられたときだけです。
それ以外は `UNKNOWN` とし、何が足りなかったかを書きます。照合するファイルが無い場合も同じです（Python の拡張モジュール
`_brotli.*so`・`brotlicffi/_brotlicffi*.so`、conda の `lib/libbrotlidec.so.*`。conda ではシンボリックリンクを数えません）。
ファイル名や置き場所がこれと合わない配布形態は、修正済みでも `UNKNOWN` になります。

コンテナの中（`--inspect-containers`）の Python は、メタデータの版だけを読み、拡張モジュールの文字列を照合しません。
そのため版が修正版以上でも `UNKNOWN` で、コンテナの中の Python が `FIXED` になることはありません。

## 版番号

- 配布元のパッケージは配布元の修正版と比べます。既知データの日付より後に出た修正は分かりません
  （`NO_FIX_AVAILABLE` が古くなっていることがある）。データの日付を見てください。
- 既知データは系列単位で、告知が影響範囲を示している行にはその範囲を持ちます。範囲より前の版は `UNKNOWN` とし、更新を
  勧めます。1.0.21 より前の Bun（GHSA-663w-cv8g-jj2p: 1.0.21〜1.4.3）、Brotli 1.0.2 以前と 0.x（GHSA-9v8h-qqgm-4m35:
  1.0.3〜1.2.0）、1.0.3 より前の PyPI の Brotli・brotlicffi（同じ告知。PYSEC-2026-4322・PYSEC-2026-4323 はこれらの版も
  影響ありとしていて、資料が食い違っています）です。影響を受けるかは告知からは分からないので、脆弱とも安全とも言いません。
  終了コードは 1 ではなく 2 につながり、要約の「更新が必要なもの」には数えません。
- Debian の `nodejs` はシステムの libbrotli を使います（`libbrotli1` で判定）。静的にリンクした配布元の
  ビルドは、版に修正の取り込みが表れないことがあるため、文字列で判定します。
- Chromium と Firefox の基準はソースツリー（third_party/brotli、modules/brotli）からのもので、ベンダーの
  告知ではありません。Chrome と Chromium 以外の Chromium 系ブラウザ（Edge・Brave など）は版で判定しません。
- サポートが終わった Node.js の系列（20 以前・21・23・25）は導出で脆弱と報告します。Node.js の勧告が
  「サポートが終わった版は常に影響を受ける」としており、修正版が出ていないためです。10 以前は `UNKNOWN`
  （Brotli を同梱する前の可能性がある）。
- 修正版と同じ番号のプレリリース（`1.4.4-rc.1`、Firefox の `150.0a1`・`150.0b3`、Node.js の nightly や `-pre`
  のビルド）は `UNKNOWN` です。修正が入る前に作られた可能性があるためです。

## プログラムの実行

正確な版を読むため、見つけたプログラムの一部を引数 1 つ（`--version`、curl は `-V`）で実行したいと尋ねます。
同意なしには何も実行しません。先に一覧を示し、事実を添えます。事実とは、root（または実行者）のほかに、本体・
パスの途中のディレクトリ・読み込むライブラリ・それを探すディレクトリを書き換えられる人と、調べられなかったことです。
端末で、全部・しない・番号で選んでもらいます。端末が無ければ `--yes` か `--no-exec` が要ります。事実は辿れる限りの
ものです: symlink は置かれた場所で辿り、ライブラリは glibc の ld.so と同じ順（必要とする側とその読み込み元の
DT_RPATH、DT_RUNPATH、ld.so のキャッシュ、既定のディレクトリ）で探しますが、実行してから開くもの（dlopen、設定
ファイル）は見えず、`$LIB` のような記号は展開しません（そのことも事実に書きます）。実行は `/` から、環境変数を
空にし、制限時間と出力の上限を付けて行います。`--inspect-containers` は、実行中のコンテナの中で決まった
スクリプトを実行します（そこでファイルを読み、見つけた `node` を `--version` で動かします）。接続先がこのホストの unix
ソケットのときだけで、その指定が同意です。

システムの道具（`readelf`・`stat`・`dpkg-query` など）は `/usr/sbin`・`/usr/bin`・`/sbin`・`/bin`（root しか
変更できなければ `/usr/local/sbin`・`/usr/local/bin` も）から使い、呼び出し側の `PATH` からは使いません。
起動するスクリプト自体は `PATH` から bash を探す（`#!/usr/bin/env bash`）ので、`sudo bash brotli-cve-check`
の形で実行してください（sudo の `secure_path` が効きます）。

## 既知データ（`--data`）

判定はこのデータで決まります。`--data` で渡したファイルを root（または実行者）以外のユーザーが変更できる場合
（ファイル自体か置き場所のディレクトリ。`--output` と同じ条件）も使いますが、結果の冒頭で警告します（JSON は
`data_writable_by_others`）。読むのは通常のファイルだけで、16 MiB まで、制限時間つきです。

## レポートの保存（`--output`）

`--output` は新しいファイルを作るだけで、既存のものを上書きも、開きもしません。保存先から `/` までのすべての
ディレクトリが root（root 以外で動くときは本人）の所有で、他のユーザーが書き込めないこと（`/tmp` のように
root 所有で sticky bit 付きなら可）が条件です。そのため root で動かすときは、一般ユーザーのホームには書けません。
そのディレクトリの持ち主が、root の書くファイルを別の場所へ向けられるためです。root で点検した結果を自分の
ホームに残すときは、標準出力をリダイレクトしてください: `sudo bash brotli-cve-check > report.txt`。

## 結果が意味しないこと

- 侵入の有無の確認ではありません。修正版に更新しても、更新前の侵入の痕跡は消えません。
- 他のホストや、動いていなかったコンテナについては何も言いません。別のホストへの接続で一覧したコンテナはそのホストのもので、
  結果には接続先が一緒に出ます。
