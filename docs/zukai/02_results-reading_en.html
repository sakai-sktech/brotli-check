How to read this page

  1. Rows are where the copy lives; columns are the OS. In the top row (shipped by the OS) the result depends on the OS. Ubuntu 22.04, 24.04 and 26.04 are all NO_FIX_AVAILABLE (waiting for the distributor): the installed 1.0.9, 1.1.0 and 1.2.0 are all inside the affected range 1.0.3–1.2.0, Ubuntu's CVE page says “Needs evaluation”, and there is no USN (26.10 is the same). In the bottom row (bundled in products) the OS does not matter: the old version is VULNERABLE, the fixed one FIXED. The test installs unfixed copies on purpose, so every run ends with exit status 1 (the correct result).
  2. Read the four-line Summary at the end. “Needs update” = VULNERABLE + LIKELY_VULNERABLE; “Needs restart” = RESTART_REQUIRED; “Needs human review” = NO_FIX_AVAILABLE + VENDORED_COPY + UNKNOWN + LIKELY_FIXED; then “Not scanned”. Example: an Ubuntu host with no bundled copies typically shows “Needs update: 0, Needs human review: 2” and exit status 2. Those two are libbrotli1 and python3-brotli, and they mean “waiting for the distributor”.
  3. Exit status 0 does not mean “safe”. It only means nothing needing action was found in the scanned ranges. The tool does not check for intrusion, and updating does not remove traces of an intrusion that happened before the update. The advisory data is a snapshot as of 2026-10-26; Ubuntu's status will change (scan again when the USN is out).
On Ubuntu, only the OS's own copy has to wait;
bundled copies can be fixed today on any OS.
