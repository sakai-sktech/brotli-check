図解 02

5 つの OS での点検結果と読み方

― brotli-cve-check ―

この1枚の読み方

  1. 行が「どこにあるコピーか」、列が OS。上の行（OS が配るコピー）は OS で結果が分かれる。Ubuntu は 22.04・24.04・26.04 とも NO_FIX_AVAILABLE（配布元の修正待ち）：入っている 1.0.9・1.1.0・1.2.0 はどれも影響範囲 1.0.3〜1.2.0 の中で、Ubuntu の CVE ページは「Needs evaluation」、USN は出ていない（26.10 も同じ）。 下の行（製品が抱える同梱コピー）は OS に関係なく、古い版は VULNERABLE、修正版に更新すれば FIXED。 テストでは未修正版をわざと入れたので、どの実行も終了コード 1 になる（これが正しい結果）。
  2. 結果は最後の「要約」4 行から読む。「更新が必要なもの」＝ VULNERABLE と LIKELY_VULNERABLE、「再起動が必要なもの」＝ RESTART_REQUIRED、 「人の確認が必要なもの」＝ NO_FIX_AVAILABLE・VENDORED_COPY・UNKNOWN・LIKELY_FIXED、「走査しなかった範囲」。 例：同梱コピーの無い Ubuntu のホストなら、典型的には「更新が必要 0・人の確認が必要 2」で終了コード 2。この 2 件は libbrotli1 と python3-brotli の「配布元待ち」という意味。
  3. 終了コード 0 は「安全」ではない。意味は「走査した範囲で対応が必要なものが見つからなかった」だけ。このツールは侵入の有無を調べず、修正版に更新しても更新前の侵入の痕跡は消えない。 既知データは 2026-10-26 時点のスナップショットで、Ubuntu の状況は今後変わる（USN が出たら点検し直す）。
Ubuntu で待つしかないのは OS のコピーだけ、同梱コピーはどの OS でも今すぐ直せる。
処方箋要約の「更新が必要」「再起動が必要」から片付け、Ubuntu は USN が出たら apt で更新して再起動し、もう一度点検する。
